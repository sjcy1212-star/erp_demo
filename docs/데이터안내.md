> 교육용 가상 자료 — 이 문서의 예시 값(회사·직원·금액)은 모두 지어낸 것입니다.

# 데이터 안내 — 직원·휴가·급여를 관리하려면 어떤 자료가 필요한가

작성일: 2026-09-14 · 대상 앱: 가온교육 인사·총무 근태 앱

## 한눈에 보기

인사 앱은 **"표 4장"** 이면 돌아갑니다. 표마다 "한 줄 = 무엇인가"가 다릅니다.

| 표 이름 | 한 줄이 뜻하는 것 | 줄 수 (우리 앱) | 이 표만의 번호 |
|---|---|---|---|
| **직원** | 사람 1명 | 24줄 | 사번 `E-1001` |
| **근태** | 어떤 사람의 **하루** | 720줄 (24명 × 30근무일) | 날짜 + 사번 |
| **휴가** | 휴가 신청 **1건** | 37줄 | 신청번호 `R-033` |
| **급여** | 어떤 사람의 **한 달 치 급여** | 12줄 (`가상_인사총무.json`) | 급여번호 `PY-2026-08-001` |

> 핵심 한 줄: **사람 정보는 직원 표에만 두고, 나머지 표에는 "사번"만 적는다.**

---

## 1. 직원 표 — "이 사람은 누구인가"

바뀌지 않는 기본 정보만 둡니다. 연차 잔여일처럼 **계산으로 나오는 값은 넣지 않습니다** (넣으면 두 곳이 어긋납니다).

| 칸 | 예시 | 왜 필요한가 |
|---|---|---|
| 사번 ★ | E-1009 | 다른 모든 표가 이 번호로 이 사람을 가리킴. **절대 바뀌면 안 됨** |
| 이름 | 도현석 | 화면에 보여줄 이름. 동명이인이 있을 수 있어 이름은 열쇠로 쓰지 않음 |
| 부서 | 개발팀 | 부서별 집계, "같은 팀 같은 날 휴가" 규칙 확인 |
| 직급 | 대리 | 화면 표시·결재선 |
| 입사일 | 2022-08-22 | **연차 계산의 출발점**, 근속 계산 |
| 재직 상태 | 재직 / 휴직 / 퇴직 | 퇴직자는 근태·급여 대상에서 제외 (우리 앱은 전원 재직으로 단순화) |

---

## 2. 근태 표 — "그 사람의 그 날은 어땠나"

| 칸 | 예시 | 왜 필요한가 |
|---|---|---|
| 날짜 ★ | 2026-09-14 | 사번과 함께 한 줄을 정함 (한 사람은 하루에 한 줄) |
| 사번 ★ | E-1009 | 누구의 기록인지 |
| 출근 시각 | 08:50 | 09:00 이후면 규칙상 지각 |
| 퇴근 시각 | 18:05 | 18:00 이전이면 규칙상 조퇴 |
| 상태 | 정상 / 지각 / 조퇴 / 결근 / 휴가 / 반차 / 미확정 | **담당자가 확정하는 최종 값.** 집계는 이 값을 셈 |
| 비고 | 병원 진료 | 사유·메모 |

> "규칙상 판정"은 표에 저장하지 않고 볼 때마다 출퇴근 시각으로 계산합니다. 저장하면 시각을 고쳤을 때 판정이 낡은 값으로 남기 때문입니다.

## 3. 휴가 표 — "휴가 신청 1건"

| 칸 | 예시 | 왜 필요한가 |
|---|---|---|
| 신청번호 ★ | R-036 | 이 신청을 가리키는 번호. 반려 사유, 히스토리 근거로 씀 |
| 사번 | E-1012 | 누가 신청했나 → 직원 표에서 이름·부서를 찾아옴 |
| 종류 | 연차 / 반차 / 병가 / 경조휴가 | 연차·반차만 잔여에서 차감 |
| 시작일 · 종료일 | 2026-09-28 ~ 09-30 | 기간 겹침 확인 |
| 사용일수 | 3 | 근무일만 셈 (주말·공휴일 제외), 반차는 0.5 |
| 차감일수 | 3 | 종류에 따라 0 (병가·경조) 또는 사용일수 |
| 사유 | 여행 | 신청 사유 |
| 신청일 | 2026-09-14 | "먼저 신청한 사람 우선" 규칙의 기준 |
| 상태 | 대기 / 승인 / 반려 | 승인된 것만 잔여 연차에서 뺌 |
| 처리일 · 처리 메모 | 2026-09-14 · 잔여 연차 부족 | 누가 언제 왜 그렇게 했는지 |

**함께 필요한 작은 표 — 연차 조정**

| 칸 | 예시 |
|---|---|
| 사번 | E-1012 |
| 적용일 | 2026-09-14 |
| 증감 | +1 |
| 사유 (필수) | 2025년 미사용 연차 1일 이월 |

이 표 덕분에 "남은 연차"를 저장하지 않고도 **부여 − 사용 + 조정**으로 언제든 다시 계산할 수 있습니다.

## 4. 급여 표 — "그 사람의 그 달 급여"

| 칸 | 예시 | 왜 필요한가 |
|---|---|---|
| 급여번호 ★ | PY-2026-08-009 | 급여 1건을 가리킴 |
| 사번 | E-1009 | 누구의 급여인지 |
| 지급월 | 2026-08 | 같은 사람·같은 달은 한 줄만 (중복 지급 방지) |
| 기본급 | 3,000,000 | 계약 금액 |
| 수당 | 200,000 | 직책·초과근무 등 (교육용은 한 칸으로 단순화) |
| 공제 | 100,000 | 세금·4대보험 자리 (교육용은 계산하지 않고 숫자만) |
| 실지급액 | 3,100,000 | **기본급 + 수당 − 공제.** 저장하지 않고 계산해도 됨 |
| 상태 | 작성 / 확정 | 확정 후에는 수정 불가 (근태 마감과 같은 발상) |

> 급여는 **근태 표와 이어집니다.** 8월 근태를 마감해야 8월 급여를 계산할 수 있고, 결근·지각 일수가 공제 계산의 재료가 됩니다. 그래서 우리 앱에서 "마감한 달은 근태를 못 고친다"는 규칙을 먼저 배웁니다.

## 5. 같은 직원의 자료를 어떻게 연결하나

### 방법: 사번 하나로 잇는다

```
직원 표 (사람 1명 = 1줄)
  E-1009 │ 도현석 │ 개발팀 │ 대리 │ 2022-08-22
     │
     │  다른 표들은 "E-1009"만 적어 둔다
     ├──▶ 근태 표   2026-09-14 │ E-1009 │ 08:50 │ … │ 미확정
     ├──▶ 휴가 표   R-009 │ E-1009 │ 연차 │ 07-06 ~ 07-08 │ 승인
     ├──▶ 조정 표   E-1009 │ 2026-09-14 │ +1 │ 이월
     └──▶ 급여 표   PY-2026-08-009 │ E-1009 │ 2026-08 │ 3,000,000 │ …
```

화면에서 "도현석"이라는 이름이 보이는 건, 앱이 매번 `E-1009`를 직원 표에서 찾아 이름을 붙여 주기 때문입니다. 근태·휴가·급여 표에는 이름이 없습니다.

### 왜 이름이 아니라 사번인가

| 이름으로 이으면 | 사번으로 이으면 |
|---|---|
| 동명이인이 생기면 누구 기록인지 모름 | 번호는 한 사람에게만 붙음 |
| 개명·오타 한 번에 모든 표가 끊김 | 이름을 고쳐도 번호는 그대로라 연결 유지 |
| "도현석"과 "도 현석"은 다른 사람 취급 | 번호는 형식이 고정 (`E-` + 4자리) |

### 연결이 만들어 내는 것 (우리 앱에서 실제로 쓰는 계산)

| 화면에 보이는 값 | 어떻게 만드나 |
|---|---|
| 직원 상세의 "남은 연차 13.5일" | 직원 표 입사일로 **부여** 계산 − 휴가 표에서 사번이 같고 상태가 승인인 줄의 차감일수 합 + 조정 표의 합 |
| 직원 상세의 "9월 지각 1건" | 근태 표에서 사번이 같고 날짜가 2026-09이고 상태가 지각인 줄 수 |
| 휴가 표의 "같은 팀 같은 날" 경고 | 신청자의 사번 → 직원 표에서 부서 → 같은 부서 다른 사람의 휴가 중 기간이 겹치는 줄 |
| 집계 탭 월 합계 | 근태 표를 달로 잘라 상태별로 셈 (직원 표는 이름·부서 붙일 때만 씀) |

### 지켜야 할 규칙 3가지

1. **사번은 만들면 바꾸지 않는다.** 퇴직해도 재사용하지 않는다.
2. **계산되는 값은 저장하지 않는다.** 남은 연차, 실지급액, 규칙상 판정은 볼 때마다 계산한다. (저장하면 원본을 고쳤을 때 어긋난다.)
3. **바꾼 이유를 남긴다.** 연차 조정 사유, 반려 사유, 처리일처럼 "누가 왜"를 표에 적어야 나중에 설명할 수 있다.

## 6. 실제 파일과 대응 — 가상 자료가 두 벌 있습니다

| 파일 | 규모 | 칸 이름 | 쓰는 곳 |
|---|---|---|---|
| `data/seed.js` (+ `seed.json`) | 직원 24명 · 근태 720줄 · 휴가 37건 | 영어 (`employees`, `attendance`, `leaves`) | 지금 앱(index.html)이 읽음 |
| **`data/가상_인사총무.json`** | 직원 12명 · 휴가 6건 · 급여 12건 | **한국어** (`직원`, `휴가`, `급여`) | 이 문서의 표와 1:1 대응. 급여까지 포함한 작은 연습 세트 |

### `data/가상_인사총무.json` 내용 (2026-09-14 생성)

정한 숫자: 3팀 × 4명 · 연차 전원 15일 일괄 · 급여 전원 같은 금액 · 휴가 대기 3 / 승인 2 / 반려 1

**직원 12명** — 사번 `H-001`~`H-012`, 경영지원팀·개발팀·영업팀 각 4명(팀장·과장·대리·사원), 전원 입사 1년 이상, 연차부여 15

**휴가 6건**

| 신청번호 | 사번 | 종류 | 기간 | 사용일수 | 상태 | 연습 포인트 |
|---|---|---|---|---|---|---|
| L-001 | H-002 강도윤 | 연차 | 08-03 ~ 08-14 | 10 | 승인 | 남은 연차 15 → 5 |
| L-002 | H-006 진수아 | 연차 | 08-19 ~ 08-21 | 3 | 승인 | 8/17 대체공휴일은 세지 않음 |
| L-003 | H-009 공태오 | 연차 | 09-04 | 1 | 반려 | 처리 메모에 반려 사유 |
| L-004 | H-003 백하람 | 연차 | 09-21 ~ 09-22 | 2 | 대기 | 정상 승인 가능 |
| L-005 | H-007 남시우 | 반차 | 09-23 | 0.5 | 대기 | 반차 = 0.5일 |
| L-006 | H-002 강도윤 | 연차 | 09-28 ~ 10-06 | 7 | 대기 | **남은 5일 < 신청 7일 → 승인 막힘** (10/3 개천절 제외) |

**급여 12건** — 급여번호 `PY-2026-08-001`~`012`, 지급월 2026-08, 전원 기본급 3,000,000 · 수당 200,000 · 공제 100,000 → 실지급액 3,100,000, 상태 "작성". 월 합계 실지급액 37,200,000원

**연차요약** — 검산용 표(사번·부여·사용·남은연차). 앱은 이 값을 믿지 않고 휴가 표에서 매번 다시 계산해야 합니다.

다시 만들려면: `node data/generate_small.js`

### 한국어 칸 이름 ↔ 영어 칸 이름

| 한국어 (`가상_인사총무.json`) | 영어 (`seed.js`) |
|---|---|
| 사번 · 이름 · 부서 · 직급 · 입사일 | id · name · dept · position · hireDate |
| 신청번호 · 종류 · 시작일 · 종료일 · 사용일수 · 차감일수 · 상태 · 처리메모 | id · type · start · end · days · deduct · status · decisionNote |
| 급여번호 · 지급월 · 기본급 · 수당 · 공제 · 실지급액 | (seed.js에는 없음) |
