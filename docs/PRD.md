## 1. 목적

"업무 앱이 **자료를 어떻게 연결하고 규칙을 어떻게 지키는지**"를 인사·총무 초보 담당자가 직접 눌러 보며 배우는 교육용 시연 앱.

- 서버·로그인·설치 없이 `index.html`을 더블클릭하면 브라우저에서 바로 돈다.
- 모든 값은 `data/가상_인사총무.json`의 가상 자료(직원 12명 · 휴가 6건 · 급여 12건)만 쓴다.
- 화면 맨 위, 맨 아래, 파일 첫 줄에 **교육용 가상 자료** 표시를 고정한다.

### 배우는 것 3가지
1. **연결** — 사번 하나로 직원·휴가·급여가 이어진다 (이름은 직원 표에서 찾아 붙인다).
2. **계산** — 남은 연차·실지급액·월 합계는 저장하지 않고 볼 때마다 계산된다.
3. **규칙** — 남은 연차보다 많은 휴가는 승인되지 않고, 확정된 급여는 고칠 수 없다.

### 대상 사용자
인사·총무를 처음 맡은 담당자, 전환 담당자. 코딩 지식 불필요.

### 3.1 직원 탭
| # | 기능 | 동작 |
|---|---|---|
| E1 | 목록 | 12명 표: 사번 · 이름 · 부서 · 직급 · 입사일 · 재직상태 · 연차 부여 · 사용 · **남은 연차** |
| E2 | 검색·필터 | 이름/사번 글자 검색, 부서 선택. 표시 인원 수를 보여 준다 |
| E3 | 상세 | 이름을 누르면 표 위에 상세 카드: 기본 정보, 남은 연차 계산식(부여 − 사용 = 남은), 이 직원의 휴가 내역 표, 이 직원의 급여 표 |
| E4 | 수정 불가 | 직원 정보는 보기만 (입·퇴사 처리는 범위 밖) |

### 3.2 휴가 탭
| # | 기능 | 동작 |
|---|---|---|
| L1 | 목록 | 6건 + 새로 등록한 건. **대기가 맨 위**, 그다음 승인·반려. 칸: 신청번호 · 직원(이름+부서) · 종류 · 기간 · 사용일수 · 남은 연차 · 사유 · 신청일 · 상태 · 처리일 · 처리 |
| L2 | 승인 | 규칙 R3 통과 시 상태 승인, 처리일 = 기준일, 처리메모 "승인". 통과 못 하면 상태 그대로 두고 버튼 아래 안내문 |
| L3 | 반려 | 버튼을 누르면 같은 줄에 "반려 사유" 입력칸 + "반려 확정 / 취소". **사유가 비면 확정되지 않는다** (R4) |
| L4 | 처리 후 | 승인·반려된 건은 두 버튼이 꺼지고 "이미 처리된 신청입니다" 표시. 되돌리기 없음 (초기화만) |
| L5 | 신청 등록 | 직원 선택 · 종류(연차/반차/병가/경조휴가) · 시작일 · 종료일 · 사유 → 등록. 사용일수는 자동 계산(R2). 상태는 대기로 시작, 신청번호는 L-007부터 이어짐 |

### 3.3 급여 탭
| # | 기능 | 동작 |
|---|---|---|
| P1 | 월 합계 | 지급월별 한 줄: 건수 · 기본급 합계 · 수당 합계 · 공제 합계 · **실지급액 합계** · 확정 건수 |
| P2 | 목록 | 급여번호 · 직원 · 지급월 · 기본급 · 수당 · 공제 · 실지급액 · 상태 · [확정] 버튼 |
| P3 | 입력 | 직원 · 지급월 · 기본급 · 수당 · 공제 입력 → 저장. 같은 직원·같은 지급월이 이미 있으면 **새로 만들지 않고 그 건을 수정**(R6). 직원과 지급월을 고르면 기존 금액이 칸에 자동으로 채워진다 |
| P4 | 건별 확정 | 목록 각 줄의 확정 버튼. 확정하면 상태 "확정", 버튼 꺼짐, 급여 입력으로 수정 불가(R7). 확정 취소 없음 |

## 4. 동작 규칙 (앱이 반드시 지켜야 하는 것)

| 번호 | 규칙 | 결정 근거 |
|---|---|---|
| **R1** | **남은 연차 = 연차 부여 − 상태가 "승인"인 휴가의 차감일수 합.** 대기·반려는 빼지 않는다. 저장하지 않고 볼 때마다 계산 | 데이터안내 3장 |
| **R2** | **사용일수 = 시작일~종료일 중 근무일 수** (토·일과 `공휴일` 표의 날짜 제외). 반차는 0.5일. 차감일수는 연차·반차 = 사용일수, 병가·경조휴가 = 0 | 데이터안내 3장 |
| R2-1 | 공휴일 표(2026-08~10)에 없는 달은 주말만 뺀다 | 기본값으로 정함 |
| **R3** | **승인 조건: 차감일수 ≤ 남은 연차.** 같으면 승인된다(남은 0일이 됨). 초과하면 상태를 바꾸지 않고 "남은 연차 N일보다 M일 많습니다. 승인할 수 없습니다" 안내 | 확인예시 3장, ≤ 는 기본값으로 정함 |
| **R4** | **반려 사유 필수.** 사유가 비면 "반려 사유를 적어야 합니다" 안내와 함께 반려되지 않는다. 사유는 처리메모에 저장 | 사용자 결정 (2026-09-14) |
| R5 | 처리된 휴가(승인·반려)는 다시 처리할 수 없다 | 데이터안내·JSON 규칙 |
| R5-1 | 휴가 신청 등록: 직원·시작일·종료일·사유 필수, 종료일 ≥ 시작일, 사용일수 0이면(근무일 없음) 등록 거부. 과거 날짜·기간 겹침은 막지 않는다 | 사용자 결정(경고·차단 안 함), 사유 필수는 기본값 |
| **R6** | **실지급액 = 기본급 + 수당 − 공제.** 저장하지 않고 계산. 같은 사번·같은 지급월은 한 건만 — 입력 시 있으면 수정, 없으면 새 건(급여번호 `PY-지급월-순번`) | 데이터안내 4장 |
| R6-1 | 금액은 0 이상의 정수. 공제가 기본급+수당보다 크면 저장 거부 ("실지급액이 음수가 됩니다") | 기본값으로 정함 |
| **R7** | **확정된 급여는 수정 불가.** 확정 건을 급여 입력에서 고르면 "확정된 급여는 수정할 수 없습니다" 안내와 함께 저장 거부 | 사용자 결정 (2026-09-14) |
| R8 | 모든 표의 이름·부서는 사번으로 직원 표에서 찾아 붙인다. 휴가·급여 표에는 사번만 저장 | 데이터안내 5장 |
| R9 | 기준일(가상의 오늘)은 2026-09-14 고정. 처리일·신청일에 이 값을 쓴다 | JSON `기준일` |

## 5. 데이터

### 5.1 원본
`data/가상_인사총무.json` (생성기 `data/generate_small.js`). 한국어 칸 이름. 구조는 `데이터안내.md` 6장.

| 표 | 줄 수 | 열쇠 |
|---|---|---|
| 직원 | 12 | 사번 H-001~H-012 |
| 휴가 | 6 (대기 3 · 승인 2 · 반려 1) | 신청번호 L-001~L-006 |
| 급여 | 12 (전원 2026-08, 상태 "작성") | 급여번호 PY-2026-08-001~012 |
| 공휴일 | 7일 | 날짜 |
| 연차요약 | 12 | 검산용. **앱은 읽지 않는다** (R1로 직접 계산) |

### 5.2 앱이 브라우저에 저장하는 것
`휴가`(상태·처리일·처리메모·새 신청), `급여`(금액·상태·새 건), 마지막 탭. 직원·공휴일은 바꾸지 않으므로 저장하지 않는다.

### 5.3 읽는 방법
`index.html`이 더블클릭(file://)으로 열려야 하므로 JSON을 fetch로 읽지 않고, 생성기가 함께 만드는 `data/가상_인사총무.js`(`window.DATA = {...}`)를 `<script>`로 읽는다.
