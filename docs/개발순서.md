# 개발 순서 — erp_small (직원 · 휴가 · 급여)

기준 문서: `PRD.md` v1.0 (기능 E/L/P/C, 규칙 R1~R9, 확인 A1~A10) · `DESIGN.md` v1.0
작성일: 2026-09-14

## 순서를 정한 원칙

1. **계산부터, 화면은 나중에.** 남은 연차·사용일수·실지급액 함수를 먼저 만들고 A1~A3 값이 맞는지 확인한 뒤 화면을 붙인다. 화면이 틀렸는지 계산이 틀렸는지 구분하기 위해서다.
2. **확인 기준(A1~A10) 순서대로 화면을 만든다.** 단계마다 "이 단계가 끝나면 A몇 번이 통과된다"가 정해져 있다.
3. **기존 앱(`app/app.js`)에서 검증된 조각을 가져온다.** 근무일수·날짜 도우미·설명 모드·초기화 확인 줄·표 렌더링 방식은 이미 24명 앱에서 동작 확인이 끝났다.
4. **디자인은 처음부터 토큰으로.** `style.css`를 DESIGN.md 0장 토큰으로 시작해 나중에 색·크기를 고치는 일을 없앤다.

- `style.css`: DESIGN.md 0장 토큰을 `:root` 변수로 옮기고 띠·머리·상자·탭·표·버튼 7종·입력칸·배지·안내문·반응형 3단계를 작성. 기존 `app/style.css`에서 가져오되 12장 차이표(둥글기 6/8px, 입력칸 34px, `tabular-nums`)를 반영.

### 2단계 — 데이터 층과 계산 함수 (40분) → R1 R2 R2-1 R6 R8 R9
`app.js` 앞부분만 작성. 화면 없음.
- 상태: `fresh()` = DATA의 휴가·급여 깊은 복사 + `tab`. `load()/save()` (localStorage 키 `erp_small_v1`). 직원·공휴일은 DATA에서 직접 읽음(저장 안 함, PRD 5.2).
- 계산: `근무일수(시작, 종료)` (주말 + DATA.공휴일 제외; 목록 밖 달은 주말만), `남은연차(사번)` = 연차부여 − 승인 차감 합, `실지급액(건)` = 기본급+수당−공제, `직원(사번)` 찾기, `기준일`.

- **확인**: 브라우저 콘솔에서 `남은연차("H-002")`→5, `실지급액(급여[1])`→3100000, `근무일수("2026-10-01","2026-10-09")`→6, `근무일수("2026-08-19","2026-08-21")`→3. (A1·A2·A3 값과 자동검사 (4)의 재료)

### 3단계 — 직원 탭 (40분) → E1~E4, A1, A2
- 목록 표(사번·이름·부서·직급·입사일·재직상태·부여·사용·남은), 검색·부서 필터·표시 인원, 이름 버튼 → 상세 카드(기본 정보, "부여 15 − 사용 10 = 남은 5" 계산식, 휴가 내역 표, 급여 표), 닫기.
- 이름·부서는 사번으로 찾아 붙임(R8). 숫자 칸 `.num` 오른쪽 정렬.
- **확인**: 강도윤 남은 연차 5일(A1), 상세의 8월 실지급액 3,100,000원(A2). 진수아 12일, 나머지 15일.

### 4단계 — 휴가 탭: 목록·승인·반려 (60분) → L1~L4, R3 R4 R5, A4~A7
- 목록: 대기 → 승인 → 반려 순, 같은 상태 안에서는 신청일 내림차순. 칸 구성은 PRD L1. 직원 칸은 이름 + 아래 작은 글씨 부서(DESIGN 7장 "열 합치기").
- 승인: `차감일수 ≤ 남은연차`면 승인·처리일·처리메모 "승인". 초과면 상태 유지 + 버튼 아래 빨간 안내 "남은 연차 N일보다 M일 많습니다. 승인할 수 없습니다."
- 반려: 같은 줄에 사유 입력칸 + "반려 확정 / 취소". 빈 사유 → "반려 사유를 적어야 합니다". 확정 시 상태 반려, 처리메모 = 사유.
- 처리된 건: 두 버튼 disabled + "이미 처리된 신청입니다 · 사유: …".
- 기존 `app/app.js` `viewLeave`의 승인/반려/inline-reject 구조를 재사용(팀 경고·결정 취소는 뺀다).
- **확인**: L-004 승인 → 승인·2026-09-14·백하람 13일(A4) / L-006 승인 → 대기 유지·"5일보다 2일"(A5) / L-006 빈 사유 반려 → 막힘(A6) / 사유 입력 반려 → 반려·강도윤 5일 유지(A7).

### 5단계 — 휴가 신청 등록 (30분) → L5, R5-1
- 폼: 직원 · 종류(연차/반차/병가/경조휴가) · 시작일 · 종료일 · 사유 · 등록. 사용일수 = 근무일수(반차 0.5), 차감 = 연차·반차만.
- 검증: 직원·사유 필수, 종료일 ≥ 시작일, 근무일 0이면 거부. 과거 날짜·겹침은 막지 않음. 신청번호 L-007부터, 신청일 = 기준일, 상태 대기.
- **확인**: 2026-10-01~10-09 연차 등록 → 사용일수 6일(자동검사 (4); 10/9 한글날 제외, 10/3은 토요일), 목록 맨 위 대기에 나타남.

### 6단계 — 급여 탭: 월 합계·목록 (30분) → P1 P2, A3
- 월 합계 표(지급월별 건수·기본급·수당·공제·실지급액 합계·확정 건수), 급여 목록 표(급여번호·직원·지급월·기본급·수당·공제·실지급액·상태·[확정]). 금액은 `toLocaleString()` + "원", `tabular-nums`.
- **확인**: 2026-08 12건, 실지급액 합계 37,200,000원(A3).

### 7단계 — 급여 입력·건별 확정 (50분) → P3 P4, R6 R6-1 R7, A8 A9
- 입력 폼: 직원 · 지급월 · 기본급 · 수당 · 공제 · 저장. 직원+지급월을 고르면 기존 건 금액이 칸에 자동 채움.
- 저장: 같은 사번·지급월 있으면 수정, 없으면 새 건 `PY-지급월-순번`. 금액 0 이상 정수, 공제 > 기본급+수당이면 "실지급액이 음수가 됩니다" 거부. 확정 건이면 "확정된 급여는 수정할 수 없습니다" 거부.
- 확정 버튼: 상태 "확정", 버튼 disabled, 취소 없음.
- **확인**: 강도윤 8월 수당 300,000 저장 → 12건 유지·실지급 3,200,000·합계 37,300,000(A8) / PY-002 확정 후 수정 → 거부·값 유지(A9).
